# T025.5: Restauracion transaccional

## Estado

Pendiente (refinada 2026-10-21 en T025).

## Objetivo

Restaurar un respaldo: verificacion completa en staging, migracion de esquema, borrado de credenciales, marcador durable, relanzamiento y sustitucion al arrancar con `pre-restauracion-<fecha>`.

## Contexto

Epica T025, decisiones D1 a D19. Ver `docs/tasks/T025-respaldo-en-la-nube.md` y `docs/meetings/T025-refinamiento/`.

## Alcance

### Incluye

- Punto de restauracion en `ArranqueProceso` tras `SingleInstanceCoordinator` y antes de T019, SQLite y worker (D13); matriz con T019.
- Detencion ordenada del executor; mtime preservado; lectura cancelable de archivos no descargados.
- ADR "Restauracion transaccional al arranque" (D15).

### No incluye

- Fusion de datos; restaurar la e.firma.

## Dependencias

- T025.1, T025.2

## Criterios de aceptacion

- [ ] [T025.2/T025.5] Ida y vuelta: base sintetica (XAXX010101000) y 3 ZIP se respaldan y restauran con SHA-256 identicos e `integrity_check` = ok; una base sin perfiles ni paquetes tambien.
- [ ] Un esquema mas nuevo se rechaza antes de tocar nada; uno anterior se migra a la version actual; tras restaurar, las credenciales quedan vacias, los perfiles muestran "requiere registrar e.firma" y no se hacen llamadas SAT hasta registrarla.
- [ ] Restaurar con una operacion SAT activa rechaza nuevas operaciones, solicita la cancelacion, espera el cierre, no aplica resultados posteriores y reinicia.
- [ ] Restaurar con otro HOME resuelve los paquetes bajo la nueva raiz y conserva su mtime (sin reindexar); un corte en cualquier fase queda recuperable al siguiente arranque sin estado mixto; `pre-restauracion-<fecha>` queda intacta y no choca con una existente; la migracion T019 no elige la carpeta equivocada; el archivo se vuelve a verificar si cambia entre verificacion y sustitucion.
- [ ] Leer un respaldo aun no descargado por el proveedor (simulado con un lector lento o bloqueante) no congela la UI y se puede cancelar.
- [ ] [T025.1/T025.5/T025.6] ADRs nuevos registrados; README y requirements actualizados.
- [ ] Build `-Werror`, `ctest` y `git diff --check` pasan; pruebas con `QTemporaryDir` y datos sinteticos.
