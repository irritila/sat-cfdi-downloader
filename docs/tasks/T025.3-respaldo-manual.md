# T025.3: Respaldo manual a la carpeta elegida

## Estado

Pendiente (refinada 2026-10-21 en T025).

## Objetivo

`RespaldoService` y puerto `DestinoRespaldo`: "Respaldar ahora" valida el destino, escribe `.partial`, publica con rename exclusivo, depura a 5 copias propias y admite cancelacion.

## Contexto

Epica T025, decisiones D1 a D19. Ver `docs/tasks/T025-respaldo-en-la-nube.md` y `docs/meetings/T025-refinamiento/`.

## Alcance

### Incluye

- Servicio en hilo propio, un respaldo a la vez (D18); progreso y tamano.
- Adaptador de sistema de archivos con inyeccion de errores para pruebas; D8, D17.

### No incluye

- Diario y Keychain (T025.4), UI (T025.6).

## Dependencias

- T025.1, T025.2

## Criterios de aceptacion

- [ ] Con un adaptador de sistema de archivos que inyecta errores: carpeta inexistente, sin escritura, volumen desmontado y disco lleno muestran su estado especifico. Ante error manejado o cancelacion (en captura, cifrado o escritura) se elimina solo el `.partial` propio; tras terminacion forzada puede quedar solo ese `.partial`, que el siguiente arranque elimina sin seguir enlaces.
- [ ] Tras publicar la sexta copia propia quedan exactamente las 5 propias mas recientes (D17); un `.afbak` ajeno, un enlace o un `.partial` ajeno permanecen; nunca se borra una copia antes de publicar la nueva; un nombre en conflicto no sobrescribe; un respaldo pedido durante otro no inicia otro (D18).
- [ ] Build `-Werror`, `ctest` y `git diff --check` pasan; pruebas con `QTemporaryDir` y datos sinteticos.

## Verificacion

`ctest`; las comprobaciones manuales indicadas en los criterios las hace el usuario en el bundle firmado.

## Resultado

Pendiente.
