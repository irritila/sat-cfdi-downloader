# T025.1: Formato y cifrado del respaldo

## Estado

Completada (2026-10-21).

## Objetivo

Contenedor `AFB1` en streaming con KDF Argon2id, DEK envuelta por contrasena y clave de recuperacion, bloques AES-256-GCM, manifiesto, escritor y lector/verificador.

## Contexto

Epica T025, decisiones D1 a D19. Ver `docs/tasks/T025-respaldo-en-la-nube.md` y `docs/meetings/T025-refinamiento/`.

## Alcance

### Incluye

- Modulo `crypto/ContenedorRespaldo` (OpenSSL >= 3.2; patron EVP de `ContenedorCredencial`), cabecera versionada con id de instalacion (D17), D9, D12, D16.
- Lector que verifica todo antes de entregar entradas; rechazo de rutas hostiles.
- ADR "Respaldo cifrado a carpeta sincronizada del usuario" y nota en README/requirements (D15).

### No incluye

- Captura de datos (T025.2), destino y publicacion (T025.3), UI.

## Criterios de aceptacion

- [x] Ningun archivo publicado, `.partial`, staging ni log contiene en claro `XAXX010101000`, `/Users/usuario` ni `<cfdi:`; el respaldo no contiene archivos de `credentials/` ni la contrasena SAT.
- [x] Alterar 1 byte de cualquier bloque, truncar el ultimo o reordenar dos hace fallar la verificacion sin modificar los datos locales; contrasena o clave de recuperacion incorrecta falla con un mensaje generico; la clave de recuperacion abre el mismo respaldo; tras cambiar la contrasena se cumple D16.
- [x] Un manifiesto con `..`, rutas absolutas o enlaces se rechaza; una fuente ZIP enlazada nunca se sigue.
- [x] Durante el cifrado y la lectura de 3 GB, despues de completar Argon2id, la memoria adicional del pipeline es <= 32 MiB; el pico del KDF se mide y reporta aparte (prueba omitible en CI).
- [x] CMake exige OpenSSL >= 3.2 y el flujo comprueba Argon2id antes de usarlo.
- [x] [T025.1/T025.5/T025.6] ADRs nuevos registrados; README y requirements actualizados.
- [x] Build `-Werror`, `ctest` y `git diff --check` pasan; pruebas con `QTemporaryDir` y datos sinteticos.

## Verificacion

`ctest`; las comprobaciones manuales indicadas en los criterios las hace el usuario en el bundle firmado.

## Resultado

- Puerto `ContenedorRespaldo` (`src/ports/respaldo/`) e implementacion `ContenedorRespaldoOpenSsl`: formato `AFB1` con cabecera de 204 B, Argon2id (minimos m=64 MiB, t=3, p=1; techo de lectura 256 MiB, t=8), DEK envuelta por KEK de contrasena y de recuperacion (HKDF-SHA256; clave de 56 caracteres Crockford Base32 con control), bloques con marco explicito y AES-256-GCM, SHA-256 por entrada y manifiesto; limites de 100 000 entradas, 16 MiB de manifiesto y 200 000 carpetas.
- Fuentes abiertas por descriptor sin seguir enlaces; extraccion solo a staging privado validado por descriptor, sin exito no confiable; `autenticarCabecera` cubre la cabecera completa y el bloque 0.
- OpenSSL >= 3.2 en CMake; ADR 0021; nota en README y requirements.
- Verificacion: build `-Werror`, `ctest` 26/26, 92 pruebas del contenedor (3 GB y 100 000 entradas aprobadas con su variable), `git diff --check`; seguridad apto tras cambios; calidad aprobada en re-revision.
- Parcial dentro del criterio de texto claro: `.partial`, staging y logs del flujo completo se comprueban en T025.3 y T025.5.
