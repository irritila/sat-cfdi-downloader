# T015.1: Lector de ZIP seguro y parser de CFDI

## Estado

Completada (2026-10-11). La prueba con XML reales se hace en T015.3.

## Objetivo

Leer de forma segura los XML dentro de un ZIP del SAT y convertir cada CFDI en un resumen y un detalle normalizados, sin UI.

## Decisiones

T015 D4, D5, D6, D10, D11.

## Alcance

### Incluye

- `domain/cfdi`: resumen (version, tipo, fecha, serie-folio, emisor y receptor con RFC y nombre, subtotal, total, moneda, metodo y forma de pago, UUID, estado de parseo) y detalle (conceptos, impuestos, relacionados, timbre, Pagos y Nomina basicos, complementos no representados), montos decimales exactos.
- Puerto `CfdiArchiveReader` y su implementacion con `libzip` (dependencia nueva en CMake).
- Parser con `QXmlStreamReader` para 4.0 y 3.3, minimo para 3.2.

### No incluye

- Indice, UI y PDF.

## Dependencias

- T008. `libzip` disponible en Homebrew.

## Criterios de aceptacion

- [x] Dado un ZIP con CFDI 4.0 y 3.3 de los tipos I, E, P, N y T, cuando se lee, entonces cada XML produce su resumen con los campos de D5/D6 y los montos coinciden exactamente con el texto del XML.
- [x] Dado un CFDI 3.2 o con un complemento desconocido, entonces se lista con los datos legibles y estado "version no soportada" o "parcial" con el nombre del complemento.
- [x] Dado un XML con `<!DOCTYPE` (incluido "billion laughs"), mal formado, con otra codificacion o mas profundo que 64, entonces ese CFDI queda "ilegible" y los demas del ZIP se leen.
- [x] Dado un ZIP con una entrada `..`, absoluta, enlace, cifrada, no XML, de mas de 16 MiB o con razon mayor a 200:1 (y mas de 1 MiB), entonces esa entrada se omite con su motivo contado y las demas se leen; nada se escribe en disco y la memoria no supera el limite por entrada.
- [x] Dado un ZIP inexistente, truncado, con directorio central corrupto, con mas de 20,000 entradas o con mas de 1 GiB descomprimido acumulado, entonces el resultado es el error tipado "paquete ilegible" (o "origen no disponible" si no existe) sin resultados parciales, sin excepcion ni cierre.
- [x] Los logs del lector y del parser no contienen RFC, nombres, UUID completos, montos, sellos, rutas ni nombres de entradas.
- [x] `ctest` pasa completo.

## Verificacion

1. Pruebas unitarias con fixtures sinteticos (RFC genericos `XAXX010101000`/`XEXX010101000`, sin datos reales) generados por las pruebas o versionados en `tests/`.
2. Prueba manual del usuario (en T015.3, cuando haya UI): en una solicitud real, elegir 3 CFDI y comparar UUID, RFC emisor y total con su XML; la evidencia registra solo "coinciden N de 3".

## Resultado

- Puerto `CfdiArchiveReader` y `LectorZipLibzip` (libzip, `ZIP_RDONLY | ZIP_CHECKCONS`, lectura acotada en trozos, limites de D4 en
  `LimitesLectorZip.h`): omite entradas con ruta invalida, enlace, cifrado, no XML, mas de 16 MiB o razon mayor a 200:1; error tipado para
  ZIP inexistente, corrupto, truncado, con mas de 20,000 entradas o mas de 1 GiB.
- Dominio `domain/cfdi` (`ImporteCfdi` exacto, UUID, tipo de comprobante, resumen y detalle) y `parsearCfdi` puro: 4.0 y 3.3 completos,
  3.2 minimo, timbre, Pagos 2.0/1.0 y Nomina 1.2 basicos, complementos desconocidos como Parcial; rechaza `<!DOCTYPE`, codificacion no UTF-8,
  profundidad mayor a 64 y limites de elementos.
- Pruebas sinteticas (zip 30 casos, parser y dominio 79 funciones); `ctest` 15/15 x3 y build `-Werror`. Revision Codex en dos partes:
  aprobada sin bloqueantes. La comparacion con XML reales del usuario queda para T015.3 (aun no hay UI).
