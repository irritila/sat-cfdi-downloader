# T005.1: UI de perfiles SAT y e.firma

## Estado

Completada

## Prioridad y tamano

- Prioridad: Alta.
- Tamano: Mediana.

## Objetivo

Permitir crear y editar perfiles SAT desde la UI, registrar su e.firma mediante `SecretStore` y mostrar si el perfil esta listo para crear solicitudes.

## Contexto

El MVP requiere un perfil SAT antes de crear solicitudes. La pantalla debe conectar la persistencia de `T003` con el almacenamiento seguro de `T005`, sin exponer secretos a QML ni a SQLite.

## Alcance

### Incluye

- Pantalla de perfiles SAT.
- Alta de RFC y edicion de los datos descriptivos del perfil.
- Lista de todos los perfiles no eliminados, incluidos los inactivos.
- Seleccion de archivos `.cer` y `.key`.
- Captura de contrasena de e.firma.
- Invocacion del caso de uso de registro de e.firma.
- Indicador de credencial valida y perfil listo/no listo.
- Mensajes visibles para validaciones y errores de Keychain.
- Reemplazo de e.firma desde la UI.

### No incluye

- Consulta SAT real.
- Creacion de solicitudes.
- Administracion de usuarios, clientes o roles.
- Exportacion o migracion de credenciales.
- CSD para timbrado.

## Decisiones cerradas del refinamiento

- Un perfil se puede crear sin e.firma. Se muestra como `SinCredencial` y no
  puede usarse para crear solicitudes hasta que el estado verificado sea
  `Lista`.
- La lista muestra todos los perfiles no eliminados. Un perfil inactivo se
  identifica como no disponible para nuevas solicitudes, conserva su RFC y su
  credencial, y no se ofrece en el selector de nueva solicitud.
- El RFC se normaliza al crear el perfil y queda inmutable después. Editar un
  perfil cambia solo su nombre descriptivo. Esto preserva la identidad fiscal,
  la credencial asociada y la deduplicacion de solicitudes.
- La unicidad de RFC aplica a todo perfil no eliminado, incluso si esta
  inactivo. Una violacion del indice se traduce a `RfcDuplicado` para la UI.
- `listoParaSolicitudes` es un valor derivado por aplicacion:

  ```text
  perfil.activo && estadoCredencialVerificado == Lista
  ```

  QML no calcula ni persiste ese valor.
- La vista primero carga el resumen persistido y verifica de forma asincrona
  las credenciales registradas. Durante esa comprobacion muestra
  `Verificando`; si Keychain no puede consultarse, muestra `Estado no
  disponible` y permite reintentar.
- La edicion del perfil y la gestion de e.firma son flujos separados. El perfil
  debe guardarse antes de habilitar Registrar e.firma o Reemplazar e.firma.
- El reemplazo exige confirmacion explicita antes de abrir el dialogo de
  captura. Si falla antes del commit, el indicador vuelve al estado real de la
  credencial anterior y comunica que sigue registrada sin cambios.
- QML solo entrega `QUrl` de archivos locales y la contrasena capturada al view
  model. El view model guarda rutas solo en miembros privados durante el envio,
  convierte la contrasena a un buffer sensible y limpia el control de entrada
  de inmediato. La limpieza de copias internas del motor QML es best effort.
- `PerfilesSatViewModel` recibe `PerfilesSatService` y
  `CredencialesSatService`; no recibe repositorios ni `SecretStore`.
- `CredencialesSatService` ejecuta validacion, Keychain y la transaccion de
  reemplazo fuera del hilo grafico. `CredencialPreparada::confirmar()` ocurre
  solo despues del commit y no debe realizar I/O.
- Los errores de e.firma incluyen un origen no sensible (`Certificado`,
  `Llave`, `Contrasena` o `Ninguno`) para enfocar el control correcto. Los
  mensajes visibles no incluyen rutas, RFC del certificado, serie, `OSStatus`
  ni material criptografico.

### Contrato de presentacion

`PerfilesSatListModel` expone por perfil: `id`, `rfc`, `nombre`, `activo`,
`preparacion`, `listoParaSolicitudes`, `verificando`, `estadoTexto` y
`vigenteHasta` opcional. La seleccion se conserva por `id`, nunca por indice.

`PerfilesSatViewModel` expone estados de lista `cargando`, `vacia`, `error` y
`conDatos`; un formulario `nuevo` o `edicion`; `rfc`, `nombre`, errores por
campo, `sucio`, `guardando` y comandos para cargar, seleccionar, crear,
guardar, descartar y reintentar el estado de una credencial.

`EFirmaFormViewModel` expone fases `capturando`, `validando`, `exito` y
`error`; basenames de certificado y llave, nunca rutas; `esReemplazo`,
`puedeEnviar`, `errorKey`, `errorMessage` y `campoConError`. Durante
`validando` impide el doble envio y conserva la UI responsiva.

Los servicios que consume la vista deben cubrir:

```text
PerfilesSatService:
  listarNoEliminados(), obtener(id), crear(rfc, nombre), actualizarNombre(id, nombre)

CredencialesSatService:
  importar(perfilId, EntradaEFirma), reemplazar(perfilId, EntradaEFirma),
  obtenerEstado(perfilId)
```

`crearPerfilSimulado` queda reservado para desarrollo y pruebas; no se expone
desde el composition root productivo.

## Pendientes no bloqueantes

- T005 debe confirmar si `numero_serie`, `vigente_desde` y `vigente_hasta`
  requieren persistencia en `credencial_sat`. Si no se agregan, la lista obtiene
  esos datos solo desde la comprobacion asincrona.
- Verificar la compatibilidad del mecanismo de despacho con entradas move-only

- Confirmar la regla verificable para `NoEsEFirma` a partir de atributos del
  certificado. T005 no debe inferirla por nombre, extensión o texto libre.
- Unificar `FakeSecretStore` como nombre de la implementacion de prueba en vez
  de `InMemorySecretStore`. (Resuelto en T005.)

## Restricciones tecnicas

- QML no lee ni almacena la llave privada. La contrasena solo vive en el control
  de entrada hasta el envio y se limpia inmediatamente despues.
- La UI no decide si certificado y llave corresponden; recibe el resultado del caso de uso.
- Las rutas completas de archivos no son propiedades, roles, señales ni
  mensajes expuestos a QML.
- La contrasena debe limpiarse despues de entregarla al caso de uso cuando sea posible.
- Los mensajes no deben mostrar rutas sensibles, contenido de certificados ni secretos.
- Un perfil no esta listo para solicitudes hasta que `SecretStore` confirme todas las validaciones.

## Criterios de aceptacion

- [x] Dada una lista vacia, cuando se abre Perfiles SAT, entonces muestra un
  estado vacio accesible y permite crear un perfil.
- [x] Dado RFC y nombre validos, cuando se guarda un perfil, entonces persiste
  el RFC normalizado, muestra `SinCredencial` y no lo ofrece para solicitudes.
- [x] Dado un perfil existente, cuando se edita, entonces solo permite cambiar
  el nombre descriptivo; el RFC se muestra como identidad no editable.
- [x] Dado un RFC ya asociado a cualquier perfil no eliminado, cuando se intenta
  crear otro, entonces muestra `RfcDuplicado`, conserva el formulario y enfoca
  el campo RFC.
- [x] Dado un perfil inactivo, cuando se muestra en la lista, entonces conserva
  RFC y estado de credencial pero se identifica como no disponible para nuevas
  solicitudes.
- [x] Dado un perfil guardado, cuando se seleccionan `.cer` y `.key`, entonces
  QML solo muestra sus basenames y el view model conserva las rutas fuera de
  propiedades, roles y señales.
- [x] Dada una contraseña capturada, cuando se envía, cancela, falla, cambia de
  perfil, navega u oculta la ventana, entonces el control queda vacío y no hay
  contraseñas o rutas en SQLite, WAL/SHM, logs, mensajes ni propiedades QML.
- [x] Dada una e.firma valida, cuando termina la validacion, entonces el estado
  pasa a `Lista` y el perfil activo queda listo para solicitudes.
- [x] Dada una contraseña incorrecta, pareja incompatible, RFC distinto,
  e.firma vencida, no vigente o no admisible, cuando se registra, entonces el
  error es visible, seguro y enfoca el control relacionado sin activar la
  credencial.
- [x] Dado un estado de Keychain bloqueado, denegado, cancelado o no disponible,
  entonces la pantalla muestra la categoria correcta sin filtrar detalles y no
  bloquea la UI.
- [x] Dada una credencial existente, cuando se solicita reemplazarla, entonces
  pide confirmacion antes de capturar archivos y contraseña.
- [x] Dado un reemplazo valido, cuando confirma el commit, entonces hay una sola
  credencial activa y el estado se actualiza.
- [x] Dado un reemplazo fallido, entonces la credencial anterior permanece
  registrada y la UI muestra su estado real, incluso si estaba vencida.
- [x] Dado el resumen de perfiles, cuando una credencial requiere verificacion,
  entonces se muestra `Verificando`; cuando Keychain no puede consultarse,
  muestra `Estado no disponible` y permite reintentar por perfil.
- [x] Dado `FakeSecretStore`, `FakePerfilesSatService` y
  `FakeCredencialesSatService`, entonces los servicios y view models cubren
  exito, errores, reemplazo y asincronia sin Keychain real.
- [x] La pagina y el dialogo se pueden recorrer con teclado, sus controles y
  errores tienen nombres accesibles y el estado no depende solo del color.
- [x] Dado Volver a solicitudes, cuando se abandona la pagina sin operaciones
  pendientes, entonces vuelve a la lista sin crear una solicitud SAT.

## Verificacion

1. Crear un perfil valido usando `FakeSecretStore`.
2. Probar RFC duplicado.
3. Probar e.firma valida, contrasena incorrecta, pares incompatibles, RFC distinto y certificado vencido.

8. Escanear con centinelas las propiedades y roles expuestos a QML, mensajes,
   logs, SQLite, WAL/SHM y temporales; el conteo esperado es cero.
9. Probar por separado la infraestructura con SQLite temporal y la presentacion
   con QuickTest, incluyendo doble envio, resultados tardios y cambio de perfil.
10. Verificar manualmente el selector nativo de archivos, VoiceOver, recorrido
    por teclado y redimensionado con fixtures de prueba.

## Definicion de terminado

- La pantalla permite administrar perfiles SAT sin acceso directo a secretos.
- El perfil muestra correctamente si esta listo para crear solicitudes.
- El registro y reemplazo de e.firma usan `SecretStore`.
- Los errores principales tienen mensajes visibles y no filtran informacion sensible.
- `T009` puede asumir que un perfil marcado como listo tiene una credencial valida.

## Riesgos y notas

- Esta tarea cubre la UI necesaria para el uso personal; no es un modulo de administracion de clientes.
- La validacion tecnica de firma SAT se realiza en `T006`; esta pantalla no sustituye ese spike.
- La limpieza de copias internas de contraseña que pueda conservar el motor QML
  es best effort. La evidencia verificable cubre controles, propiedades,
  modelos, mensajes, logs, SQLite y temporales.
